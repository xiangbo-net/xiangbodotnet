## 三、最终实现要点

**技术**
- 单个 HTML：HTML/CSS/JS/字表全部内联，零依赖、零后端、零 CDN、零音频文件
- 拖拽用 Pointer Events（鼠标与触摸统一）；音效用 Web Audio 实时合成；朗读用系统语音
- 数据存浏览器 localStorage（进度、每字掌握状态、能量、历史、设置）
- 开发方式是「分文件 + 构建脚本合并」：`src/` 源码 → `node tools/build-app.cjs` → 单文件

**体验**
- 汉字用**楷体**渲染（Kaiti SC / STKaiti），字号最大 260px——识字场景楷体比黑体更友好
- 配色语义：认识 = 暖橙/金，不认识 = 蓝灰，**全站无红色**；图标 + 颜色双通道
- 无倒计时、无失败、无广告、无弹窗
- 布局：横屏三栏（左投放区 / 中间大卡 / 右投放区）；竖屏改为卡片在上、两个投放区左右并排，保持「左=认识、右=不认识」映射一致

**游戏化**
- 能量：每张 +5、连击 +10、完成一局 +20；称号 6 级（新手上路 → 汉字大师），升级全屏奖章
- 只奖励「完成」不奖励「认识」——这是本项目的核心设计约束

## 五、开发中发现的真实问题（已修）

1. **cnchar 拼音声调大量出错** → 本来打算用它出拼音，交叉核对时发现「丽→lí、沙→shà、雨→yù、打→dá、主→zhù」这类错误，改以 pinyin-pro 为主源。
2. **多音字表重复键静默覆盖** → 我的校准表里 `重`、`着`、`曲`、`转` 各写了两次，JS 对象后值覆盖前值，结果「重」被标成 chóng（应是 zhòng）。已去重并加了「校准生效清单」写进 QA 报告。
3. **组词取到人名/音译名** → 「米→艾米/汤米」「禾→高君禾」「克→杰克」，改成只取双字词并优先「整词都在字表内」。
4. **「认识」"不认识"图标渲染成皱眉脸** → 截图验收时发现右侧是个沮丧脸，违背「不给负反馈」，改成中性好奇脸。
5. **竖屏布局把投放区撑满整屏** → grid 的 1fr 行被分配给了投放区，改为卡片占主区、两个投放区并排在下方。
6. **「看拼音」按钮点击抛异常** → 代码里误把 DOM 元素传给了 `querySelector`，拼音能显示但按钮文字更新崩溃（无头实测抓出来的）。

## 六、边界与未做（明确说明）

- ❌ 不做账号 / 云端同步 / 多设备同步 —— 数据只在当前浏览器本地
- ❌ 不做笔顺动画、写字教学 —— 这是认字量测试，不是识字课
- ❌ 不做语音识别自动判读 —— 不可靠，改用「家长判读模式」
- ⏸ 虚拟形象养成（小宠物/贴纸）留到 v2
- ⚠️ **识字量是估算值**：按本局比例外推，测 20 张时误差较大，页面已明确标注
- ⚠️ **字表是"教学顺序近似"**：以小学低年级常用字圈定 300 字 + 高频字补足 700 字，不宣称与某版教材逐字对齐。如需严格对齐某版教材，替换 `src/base-chars.json` 重跑构建即可
