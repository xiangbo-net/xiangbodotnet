案例101｜团队会议管理

使用说明

1.
本案例把「团队会议管理」拆成 6 个步骤（步骤 0 环境准备 → 步骤 5 企业微信通知）；每步给出可直接复制的提示词（置于代码块内）。
2.
按顺序逐段复制执行；每步先读「业务目标」，再把该步代码块中的提示词整体复制到 WorkBuddy 会话中运行，上一步产物核对无误后再进入下一步。
3.
材料与模板已就位：01-input/ 放会议通知、上次会议纪要、项目资料、录音转写；02-working/ 放会议纪要模板与《企业微信通知权限开通指引》；产物统一存 03-output/，行动台账存 04-archive/会议行动台账.xlsx。
4.
步骤 3 需要会议录音（可直接上传，也可指定本地文件夹由 AI 读取）；步骤 5 需要 WorkBuddy 已连接并授权企业微信「消息」权限。
5.
人工确认红线：会议结论与行动项（负责人、截止时间、验收标准）必须确认后才写入台账；企业微信通知展示并确认「发送」后才实际发出。

步骤 0｜环境与准备

业务目标：确认案例运行环境就绪，避免执行到一半才发现缺连接器、缺资料。

plain text
在开始会议管理流程前，请先做环境自检并逐项确认：
1. 工作空间目录是否包含 01-input（会议资料）、02-working（模板）、03-output（产物）、04-archive（历史台账与示例）四个目录；
2. 企业微信连接器是否已连接并授权「消息」权限（可查看 02-working/企业微信通知权限开通指引.md）；
3. 01-input 中是否已有本次会议资料（会议通知、上次会议纪要、项目资料、录音转写等）。
检查完成后，逐项汇报结果；如有缺失，先补齐再进入步骤 1。

步骤 1｜会前资料整理与议题确认

业务目标：读取 01-input 全部资料，总结上次会议纪要、列出本次会议议题，并核对「议题 ↔ 参考资料」是否一一对应；若没有议题或资料，则请用户输入会议议题并上传资料。本步产出「会前资料清单 + 优先讨论问题 + 上次跟进事项进度」，与用户确认议题后才进入下一步。

plain text
你是制造企业的会议运营助理。本步骤目标：完成会前资料整理与议题确认。只做会前整理，不生成会议纪要，不补造事实。

一、明确任务目标
读取 01-input/ 目录下全部资料（会议通知、上次会议纪要、项目资料文件夹、公司档案等），完成三件事：
1) 总结上次会议纪要要点（结论、行动项及状态）；
2) 从会议通知中列出本次会议议题；
3) 检查每个议题是否有对应的参考资料，形成一一对应关系。

二、阅读输入材料
- 上次会议纪要.docx：提取上次会议结论、行动项编号/负责人/截止时间/状态/结果备注；
- 会议通知.docx（会议通知-主题-日期）：提取本次议题、负责人、预计时长、需准备资料、目标输出及会议要求；
- 项目资料文件夹/：按议题归类（如交付计划、质量异常、客户变更等），标注每份资料支撑哪个议题；
- 公司档案.docx：了解参会岗位与职责，便于后续分工判断。

三、反问补缺（如有缺口先提问，不要猜）
- 若存在「有议题无资料」或「资料明显不完整」（如客户书面样稿未取得），逐条列出缺口，并询问用户是否需要补充上传；
- 若完全没有会议议题或资料，请直接请用户输入本次会议议题并上传相关会议资料，收到后再继续；
- 本次确认前不进入下一步。

四、处理框架
1. 输出「会前资料清单」表格：资料名称 / 对应议题 / 提供人或来源 / 是否齐全 / 缺失或待确认内容 / 建议会前补齐动作；
2. 单独列出「本次会议必须优先讨论的 3 个问题」，判断依据只能来自已提供资料；
3. 汇总「上次会议跟进事项进度」：原编号 / 原负责人 / 原截止时间 / 当前状态 / 已有或缺失证据 / 本次处理建议，供步骤 2 使用。

五、生成备选方案
对每一处资料缺口，给出至少两种处理建议（例如：会前补齐资料 / 会上口头澄清并会后补证据 / 调整议题范围），并标注推荐方案。

六、对产物进行质检
自查：议题是否与资料一一对应；是否遗漏上次未完成行动项；3 个优先问题是否有资料依据；是否出现资料之外的臆测内容；表格是否可直接阅读。

七、输出与确认
将「会前资料清单 + 优先讨论问题 + 上次跟进事项进度」展示给用户，请用户确认本次会议议题无误后，再进入步骤 2。
最后请询问用户：是否需要将本次「会前资料整理」流程沉淀为可复用的方法或模板？

步骤 2｜生成会议议题讨论稿

业务目标：基于步骤 1 已确认的议题与资料，生成「会议议题讨论稿」，作为会上讨论与拍板的依据。讨论稿第一部分 = 上次会议跟进事项进度更新（含资料中涉及的上次跟进事项，同步并入当前议题）；第二部分 = 按议题逐一列出议题、背景事实、待澄清事实、需要讨论的问题。

plain text
你是制造企业的会议运营助理。本步骤目标：生成一份「会议议题讨论稿」文件，供会议主持与讨论使用。

一、明确任务目标
生成文件：03-output/会议议题讨论稿-<会议主题>-<日期>.docx（例如：会议议题讨论稿-生产与交付周例会-2026-08-20.docx）。结构固定为两部分：
- 第一部分：上次会议跟进事项进度更新（放讨论稿最前）；
- 第二部分：本次议题讨论稿（按议题逐一展开）。

二、阅读输入材料
- 步骤 1 已读取并确认的 01-input 全部资料与「会前资料清单」；
- 步骤 1 用户补充上传的新资料（如有）；
- 上次会议纪要中的行动项与进度核对结果。

三、反问补缺
- 若资料不足以支撑某议题（缺关键数据、书面凭证等），在「待澄清事实」中列明，并标注「会前需向用户确认」的问题，不自行猜测；
- 若用户在上一步补充了资料，先纳入阅读范围再生成。

四、处理框架
1. 第一部分（上次跟进事项进度更新）：逐条列示上次行动项：原编号 / 行动项 / 负责人 / 原截止时间 / 当前状态（已完成、进行中、未完成）/ 已有证据 / 本次处理建议（关闭、继续跟进、升级、转为新行动项）。该部分必须放在讨论稿最前；
2. 第二部分（议题讨论稿）：按议题逐一组织，每个议题包含四要素：
   - 议题名称（附提出人、优先级）；
   - 背景事实（只能来自资料，写清时间、数量、责任人等可核验事实）；
   - 待澄清事实（列出缺口与需要补齐的证据）；
   - 需要讨论的问题（3-5 个，动词开头、可当场回答、不含模糊表述）；
3. 若资料中涉及上次跟进事项，将其同步并入对应议题的讨论部分，避免重复列示。

五、生成备选方案
对每个「待澄清事实」，给出 1-2 种会前或会上处理方案（例如：会上直接拍板 / 会后补充证据再定），供主持人在会上选择。

六、对产物进行质检
自查：第一部分是否覆盖全部上次行动项；每个议题是否具备「背景-待澄清-讨论问题」三段；是否出现「尽快、持续跟进、视情况」等模糊表述；讨论稿中是否有资料之外的臆测内容；命名是否符合「会议议题讨论稿-主题-日期」。

七、输出与确认
将讨论稿保存到 03-output/ 并在对话中展示要点，请用户核对；确认后进入下一步。
最后请询问用户：是否需要将「议题讨论稿」的生成结构沉淀为可复用模板？

步骤 3｜会议录音与转写

业务目标：完成会议录音的获取与文字转写，为生成会议纪要准备文本素材。支持两种输入方式：手工上传录音文件，或指定本地文件夹中的录音文件。

plain text
你是制造企业的会议运营助理。本步骤目标：获取本次会议录音并转写为文字稿，为生成会议纪要准备文本素材。

一、明确任务目标
获取会议录音并转写为文字稿，保存为 03-output/会议录音转写-<会议主题>-<日期>.txt（例如：会议录音转写-生产与交付周例会-2026-08-20.txt）。

二、输入方式（二选一，请用户明确选择）
1. 手工上传：请用户直接上传录音文件（mp3 / m4a / wav 等）；
2. 指定本地文件夹：请用户告知本地录音文件路径（例如 01-input/ 或 01-input/项目资料文件夹/ 或其他指定目录），由我读取该文件。

三、反问补缺
- 若录音无法获取或当前环境不具备转写能力，请明确告知用户，并请用户直接提供转写文本或使用其他转写工具生成后上传；
- 若录音包含多段或多位发言人，按发言顺序保留段落结构；能识别发言人则标注，不能识别则标注「发言人未识别」；
- 转写中不要修正原话、不要补全内容，保留原始表述。

四、处理框架
1. 获取录音文件后调用转写能力生成文字稿；如无转写能力，请给出替代方案并请用户提供转写文本；
2. 按时间顺序整理转写稿，保留关键时间点与承诺语句（负责人、截止时间、验收标准）；
3. 将转写稿保存至 03-output/，并按「会议录音转写-主题-日期」命名。

五、生成备选方案
若转写质量不佳或存在缺失段落，提供备选：A. 基于现有转写文本继续（在纪要中标注缺漏）；B. 请用户补充缺失片段后再继续。

六、对产物进行质检
自查：转写稿是否完整覆盖录音内容；关键承诺、负责人、截止时间是否保留原文表述，未被擅自修正或润色。

七、输出与确认
展示转写稿全文或摘要，请用户确认无重大遗漏；确认后进入下一步。
最后请询问用户：是否需要将「会议录音转写」操作流程沉淀为可复用指引？

步骤 4｜生成会议纪要并同步行动台账

业务目标：基于录音转写文本 + 用户补充资料生成会议纪要（参考 02-working/会议纪要模板.docx，无模板则先生成模板），输出到 03-output/会议纪要-主题-日期.docx；随后同步更新行动台账（04-archive/会议行动台账.xlsx：写入新任务、更新原有任务状态），实现「纪要 → 台账」闭环。

plain text
你是制造企业的会议运营助理。本步骤目标：生成会议纪要，并完成「纪要 → 行动台账」的同步闭环。

一、明确任务目标
1. 生成会议纪要：03-output/会议纪要-<会议主题>-<日期>.docx（命名格式：会议纪要-主题-日期）；
2. 同步更新行动台账：04-archive/会议行动台账.xlsx（写入本次新任务、更新原有任务跟进状态，保留历史记录不删除）。

二、阅读输入材料
- 会议录音转写（步骤 3 产物）；
- 上次会议纪要、步骤 2 的会议议题讨论稿（含上次跟进事项进度）；
- 用户补充提供的其他资料（如有）；
- 会议纪要模板：02-working/会议纪要模板.docx；若模板不存在，先按标准结构生成模板再使用。

三、反问补缺
- 转写或资料中未明确的信息（负责人、截止时间、验收标准缺失）一律写入「待确认问题」，不自行补写；
- 如需用户确认的事项较多，先列出待确认清单，不阻塞整体生成。

四、处理框架
1. 生成纪要，参考模板结构：会议基本信息 / 会议结论 / 已确认决议 / 上次行动项核对 / 本次行动项 / 待确认问题 / 下次会议核对事项；
2. 行动项规则：每条包含编号（A-YYYYMMDD-NN）、动词开头的行动项、唯一直接负责人（协作人写入备注）、截止时间、可核验的验收标准、状态；不允许「尽快、持续跟进、视情况」等模糊表述；没有明确时间写「待确认」；
3. 更新台账：将本次新行动项写入「行动项台账」工作表；对上次行动项更新状态（已完成 / 进行中 / 受阻 / 已关闭），保留历史记录；如有需要同步「跟进节奏」工作表。

五、生成备选方案
若台账与纪要行动项存在冲突（例如某行动项在会中被取消或合并），提供两种处理：A. 以纪要为准更新台账；B. 保留台账原记录并在备注标注变更原因。请用户选择。

六、对产物进行质检
自查：纪要是否覆盖全部会议结论与行动项；行动项字段是否完整（负责人 / 截止 / 验收 / 状态）；台账与纪要是否一致（新增条数、状态更新）；纪要命名是否符合「会议纪要-主题-日期」。

七、输出与确认
展示纪要要点与台账更新摘要，请用户核对；确认后进入下一步。
最后请询问用户：是否需要将「纪要 → 台账」同步流程沉淀为可复用脚本或方法？

步骤 5｜提取纪要要点并通过企业微信通知

业务目标：从会议纪要中提取要点（结论、决议、待确认问题）与待办事项（行动项），生成纯文本通知，展示核对后通过已授权企业微信连接器发送给用户（默认发送到「我与机器人的最近会话」）。

plain text
你是制造企业的会议运营助理。本步骤目标：提取会议纪要要点与待办事项，并通过企业微信通知用户。

一、明确任务目标
1. 从会议纪要中提取要点（会议结论、已确认决议、待确认问题）与待办事项（行动项清单）；
2. 生成通知文案，经用户确认后通过已授权企业微信连接器发送。

二、阅读输入材料
- 步骤 4 生成的会议纪要（03-output/会议纪要-<会议主题>-<日期>.docx）；
- 行动台账（04-archive/会议行动台账.xlsx）作为待办清单来源。

三、反问补缺
- 若纪要中行动项字段不全（缺负责人、截止时间、验收标准），先向用户确认补齐，不默认填充；
- 发送对象默认是「我与机器人的最近会话」；如需发给其他人，请用户明确接收人。

四、处理框架
1. 提取要点：会议结论、已确认决议、待确认问题（简明列出，不含敏感信息）；

操作步骤

1.

2.

5.
逐条核对：把 AI 出的纪要与你自己人工整理的实际结果比对，标出漏项、错记与口径偏差。
6.

7.

应收视角：账龄分布 → 逾期分级 → 风险客户排行。

操作步骤

1.
定用途与读者：谁看（老板 / 财务 / 业务负责人）、多久看一次、看完要做什么决策。
2.
定指标与口径：列出核心指标（现金余额、资金缺口、应收逾期率、毛利变化等），每个指标写清计算公式与数据来源。
3.

4.
让 AI 先对口径：要求它复述每个指标的定义与算法，指出数据中缺失、重复、口径不一致的地方，先补齐再算。
5.

7.

8.
人工复核：抽查 2–3 个关键数字手工重算，确认与看板一致。
9.

本实操的硬性边界：禁止自动执行对外披露财务数据；看板数字必须可追溯到原始数据，对外发布前一律由财务负责人确认。

指标与口径表 1 份：指标 / 计算公式 / 数据来源 / 预警阈值。

•
数据看板 1 份（含图表与预警标记）。

实操七｜开发一个小应用

把工作中一个反复要人工登记、查询、统计的小场景，做成一个能用的表单小应用，跑通「提交 → 存储 → 查询」的闭环。

练习目标

体验用 AI 从零做一个内部小工具，理解「字段设计 → 表单 → 数据存储 → 查询统计」的最小闭环，并清楚上线前要检查哪些事项。

可参考案例

案例 303 · 车辆预约登记系统
骨架：场景与字段设计 → 状态流转 → 表单页 → 数据列表 → 查询筛选 → 权限说明。

操作步骤

1.
选场景：找一个当前用微信、纸质或 Excel 手工登记、需要多人填、事后要统计的小场景（用车申请、会议室预约、物品领用、报修登记等）。
2.
定字段：列出必须采集的字段（申请人、时间、事由、审批人、状态），区分必填与选填，标明字段类型。
3.
定状态流转：写清一条记录会经历哪些状态（待审 → 已通过 → 已完成 / 已取消），以及谁能改状态。
4.
让 AI 先出方案：要求它先说明准备用什么方式存数据、有哪些限制与前提，确认可行再动手。
5.
生成应用：输出可运行的小应用（表单页 + 数据列表 + 查询筛选），逐个功能确认。
6.
加校验：必填项校验、时间范围校验、重复提交校验。
7.
自测：换不同角色各提交几条记录，检查数据是否落库、能否按条件查到、状态流转是否正确。
8.
写使用与权限说明：谁能看全部数据、谁能修改、数据存在哪里，附一页使用说明。

本实操的硬性边界：禁止自动执行审批、付款等业务动作；同时注意涉及员工个人信息的字段不得超出必要范围收集，内部数据应用不得直接公开到公网。

输出结果要求

•
场景说明与字段清单 1 份。
•
状态流转说明 1 份（状态 + 可操作角色）。
•
可用的小应用（表单 + 列表 + 查询筛选）。
•
自测记录 1 份：不同角色、不同条件各若干条。
•
使用说明与权限说明 1 份。
进阶班 · 实操练习 · 模块四 数字员工

实操八｜搭建一个持续使用的数字员工

把前面练过的能力组合起来，为一项需要长期重复执行的工作搭一个「数字员工」：定时跑、自动出结果、按规则通知人，并留下可追溯的运行台账。

练习目标

从「做一次」升级到「长期跑」：学会把任务拆成定时触发、自动执行、人工确认、台账留痕四个部分，并明确哪些环节必须保留人的确认节点。

可参考案例

案例 401 · 绩效评估与薪酬核算辅助
取数核验 → 评估辅助 → 核算草稿，人工确认红线最重的 HR 数字员工。
案例 403 · 设备巡检记录智能分析及周报
记录汇总 → 异常识别 → 周报生成，典型的「定时跑 + 出结果」结构。
案例 404 · 现金流预测与资金缺口看板
周期性更新数据 → 预测 → 缺口看板，数据定期刷新、看板持续可用的范本。
案例 405 · 财务报表自动体检与经营周报
报表体检 → 指标解读 → 经营周报，每周固定输入、固定产出的完整闭环。
案例 406 · 应收账款逾期风险看板
定期扫描 → 逾期分级 → 风险提醒，按账期持续盯、自动催办的典型。

操作步骤

1.
选一项长期重复的工作：至少每周做一次、有固定输入、有固定输出（周报、异常汇总、库存预警、巡检分析、应收提醒等）。
2.
画运行图：写清触发时间（每天 / 每周几几点）→ 输入来源 → 处理步骤 → 输出产物 → 通知谁 → 谁确认。
3.
定自动化边界：明确哪些步骤 AI 全自动完成，哪些必须停下来等人确认才能继续。
4.
备材料与模板：把输入材料位置、输出模板、通知话术固定下来，确保每次运行都用同一套标准。
5.
搭流程：把步骤拆成可独立运行的提示词并按顺序串起，确认每一步的输入依赖上一步的输出。
6.
设定时任务：按运行图配置定时触发，先跑一次试运行，检查是否按时产出了正确产物。
7.
建运行台账：记录每次运行的时间、输入条数、产物路径、异常项、确认人、确认结果。
8.
设异常兜底：写清数据缺失、格式错误、输出不完整时怎么办（跳过 / 标注 / 通知人工处理），一切正常则不加打扰。
9.
试用两周并复盘：记录误报、漏报与人工干预次数，据此调整规则与触发频率。

本实操的硬性边界：禁止自动执行审批、付款、处罚、录用、外发、系统写入；数字员工只做起草、汇总、标注、提醒，最终动作一律由人确认后执行。

输出结果要求

•
数字员工运行图 1 份：触发 / 输入 / 步骤 / 输出 / 通知 / 确认。
•
提示词流程 1 套（分步骤、可按序执行）。
•
已配置的定时任务，含首次试运行记录。
•
运行台账 1 份（模板 + 至少 1 次运行记录）。
•
异常兜底规则 1 份。
•
两周复盘记录 1 份：误报、漏报、人工干预次数与调整项。
